# slack-off-police (サボり警察)

Claude Code / Codex にデバイスの操作権を渡して、勉強・作業のサボりを検知したら
問答無用でプロセスを強制終了させる、Windows専用のネタ実装です。

## できること

1. エージェント（Claude Code または Codex）がチャットで「監視対象ディレクトリ」「作業テーマ」
   「進捗の判定方法」「判定間隔」「落としていいアプリ/サイト」をヒアリングする（初回のみ）
2. 設定を対象ディレクトリに保存し、以降は同じディレクトリなら再ヒアリング無しで起動
3. エディタが起動している間だけ、一定間隔で証拠（差分・操作履歴・ウィンドウ・作業状況）を集める
4. 自分自身のCLI（`claude -p` / `codex exec`）に「この期間、作業していたか」を判定させる
5. 作業していなければ煽り文をポップアップ表示＋音声再生。1回目は警告、
   2回連続なら**確認なしで**kill対象のプロセスを強制終了
6. エディタが閉じられたら作業セッション終了とみなして監視も終わる

```
エディタ起動中?
   ├ いいえ（まだ一度も起動していない）─→ 待機。判定もしない
   ├ いいえ（さっきまで開いていた）    ─→ 作業セッション終了とみなして監視を終わる
   └ はい
        ↓
   証拠を集める（コード差分・操作履歴・ウィンドウ・作業状況・時間の文脈）
        ↓
   自分のCLIに「この期間、作業していたか」を判定させる（claude -p / codex exec）
     ├ 呼び出し失敗    ─→ 見逃す（フェイルセーフ。誤爆のほうが害が大きい）
     ├ 作業していた    ─→ 何もしない
     └ 作業していない  ─→ ここから先は機械的:
            1回目   : 警告ポップアップ＋音声
            2回連続 : そのうえで kill対象があれば強制終了（無ければ警告だけ）
```

作業テーマに関係する内容（技術解説動画や公式ドキュメント）を見ている場合や、AIに質問して
いる場合は作業中と判定される。逆に、YouTubeを開いていなくても作業の痕跡が何も無ければ警告が出る。

**休憩の忖度はしない。** 休憩するときは自分で監視を止める前提。エディタを閉じれば監視も終わる。

## 2つのエージェントで同じスキルを共有する

判定に使うCLIはバックエンドとして差し替えられる。設定ファイルの `agent` が
`claude` なら `claude -p --json-schema ...`、`codex` なら `codex exec --output-schema ...`
を呼ぶ。プロンプトと出力スキーマは共通なので、判定基準はどちらでも変わらない。

```bash
python scripts/setup.py --dir ... --agent claude   # Claude Code から使うとき
python scripts/setup.py --dir ... --agent codex    # Codex から使うとき
```

`--agent auto` は環境変数とPATHから推測するが、タスクスケジューラ経由の起動では
当たらないことがあるので、スキル利用時は明示するのが前提。

バックエンドを増やす場合は `scripts/backends/<name>.py` に `cli_path()` と
`run(instruction_lines, payload, model)` を実装し、`backends/__init__.py` に登録する。

## AIは何を見て判断しているか

機械的なのは「エディタが起動しているか」「対象ウィンドウの検出（正規表現）」
「1回目は警告、2回連続でkill」だけ。**「作業していたか」の判断はすべてLLMに任せる**。
渡すのは次の7ブロック。

| ブロック | 中身 |
| --- | --- |
| `work_theme` | 初回に設定した長期の作業テーマ |
| `rules` | ユーザーが自然言語で決めた例外ルール（`--rules`） |
| `context` | 現在時刻・曜日・監視開始からの経過・警告回数・直近4回の判定履歴 |
| `work_state` | ブランチ名・直近3コミット・未コミット変更・`TASKS.md` |
| `window_titles` | 開いているウィンドウ |
| `diff` | コードの差分 |
| `activity` | AIへの質問・資料閲覧・保存 |

判定器は `slacking` と一緒に **`doing`（いま何をしているかの推定）** を返す。これが次回の
`context` に履歴として入るので、「直前まで3時間書いていた」「直前も同じ動画で警告した」を
踏まえた判定になる。例外ルールは `--rules "12時台の昼休みは自由"` のように書けば、
その時間帯だけ見逃すようになる。

## コードを書いていない＝サボり、ではない

資料を読んでいる時間やAIに質問している時間も作業のうちなので、エージェントとVS Codeが
自分で保存しているデータを読んで判定材料に加える。

| 見たいもの | 読む場所 |
| --- | --- |
| AIエージェントへの質問 | `~/.claude/projects/<cwd>/*.jsonl`、`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` |
| AIチャットでの質問 | `workspaceStorage\<id>\chatSessions\*.jsonl`、`chat.ChatSessionStore.index` |
| 資料・ファイルの閲覧 | `state.vscdb` の `history.entries`（最近開いた順を毎回比較） |
| 保存した編集 | `%APPDATA%\Code\User\History`（ローカル履歴。git管理外でも効く） |

VS Code / Insiders / VSCodium / Cursor / Windsurf などの派生も同じ構造なので同様に読む。
対象ディレクトリを開いているワークスペースだけが対象。

エージェントのトランスクリプトは、設定した `agent` に関係なく Claude Code と Codex の両方を読む
（判定はClaudeでも質問はCodexに投げているかもしれないため）。対象ディレクトリで投げた質問だけを
拾い、判定器自身の呼び出しは `--no-session-persistence` / `--ephemeral` で記録されないので、
自分の判定がユーザーの質問に化けることはない。

「何分読んでいたか」まで見たい場合は、同梱の拡張機能 `vscode-extension/` を入れると
開いた瞬間・スクロール・選択・保存が秒単位で記録される。記録するのはファイルパスと
種別だけで、ファイルの中身やチャット本文は書き出さない。

## 動作環境

- Windows
- Python 3.9+
- `pip install psutil pywin32 pyyaml`
- `claude` または `codex` CLI（サボり判定に使用。無い場合は `--no-llm` でキーワード判定のみになる）

サボり判定は各CLIのサブスク枠で動く。**API課金は発生しない。**
1回の判定に10〜20秒、発動するのは「進捗ゼロかつ対象ウィンドウあり」のときだけ。

## セットアップ

エージェントにこのスキル(`SKILL.md`)を読ませ、監視したいディレクトリで
「勉強サボったら止めて」のように話しかけてください。ヒアリング〜起動までを
エージェントが対話的に行います。

手動で使う場合:

```bash
# 初回設定
python scripts/setup.py --dir "C:/path/to/project" --agent claude --targets "YouTube,Steam" --theme "Rustで自作CLIツールを書く"

# 監視開始（フォアグラウンドで確認したい場合）
python scripts/monitor.py --dir "C:/path/to/project" --audio "assets/your_audio.mp3"
```

常駐させる場合はタスクスケジューラに登録する（詳細は `SKILL.md`）。

## 注意事項

- **2回連続でサボり判定されると、確認なしでプロセスをkillします。**
  保存前のファイルが消える可能性があります。自己責任で。
- ウィンドウタイトルもエディタの活動履歴も、外部が中身を決められる文字列なので、
  判定器にはツールを無効化した状態で渡し、kill対象の選定はローカル判定に固定しています。
- **AIエージェントやVS Codeに投げた質問文は既定でLLMに渡ります。** 嫌な場合は `--no-chat-text`、
  エディタを一切見せたくない場合は `--no-vscode` を指定してください。
- マッチはウィンドウタイトル／プロセス名で行いますが、killは**プロセス単位**です。
  対象タブを開いていたブラウザのプロセスごと落ちるため、他のウィンドウ・タブも巻き込まれます。
- `explorer.exe` などのシステムプロセスと、監視スクリプト自身・その親プロセスは
  キーワードに関わらずkill対象から除外されます。
- 音声ファイルは同梱していません。`assets/README.md` を参照してください。
  実在の配信者・VTuberの音声を無断でリポジトリに含めるのはやめましょう。
- 記事・ネタ用の実装であり、長時間の実運用は想定していません。
