# CSV一括登録機能 実装計画（修正版の例）

[完成例](sample-plan.md)を基準版として承認した後に、次の指示が入った場合の修正版の例。「今回の修正」には意味が変わった箇所だけを載せる。作成中や監査で直した箇所、言い換えだけの変更は載せない。詳細は変更のあった工程（Phase 2・5・6・7）だけを示す。

- 登録実行中の失敗は部分成功とし、保存済みの行を残す（Phase 2 で決める予定だった判断）。
- 失敗した行を修正して再投入できるよう、CSVで出力したい。
- 本番は一部の管理者へ先行公開してから全体へ広げる。

| ID | 種別 | 対象 | 修正内容 | 理由 |
|---|---|---|---|---|
| R1 | 人間判断の確定 | Phase 2・5・6 | 登録実行中の失敗は部分成功とし、保存済みの行を残して未保存の行だけを再実行する | 大きなCSVを最初から登録し直さずに済むようにするため |
| R2 | 作業追加 | Phase 5・6 | 失敗した行と理由をCSVで出力する作業を追加 | 利用者が失敗した行だけを修正して再投入できるようにするため |

## 0. 全体概要

### 0.1 目的

管理画面からCSVの全行を事前検証し、不正データが1件でもあればCSVによる登録を0件に保つ。登録実行中に失敗した場合は保存済みの行を残し、利用者が未保存の行だけを修正して再実行できる顧客一括登録機能を作る [R1]。

### 0.2 全体作業マップ

| 工程 | 主な作業 | 確認事項 |
|---|---|---|
| Phase 1 現行把握 | 現行の登録経路を整理 | 管理画面以外の登録経路と共有処理も把握できているか |
| Phase 1 現行把握 | 既存のデータ制約を整理 | 必須項目や重複条件を新経路でも維持できるか |
| [Phase 2 仕様確定](#phase-2) | 入力条件を確定 | CSV内重複と既存顧客重複を含む全行検証の条件が明確か |
| [Phase 2 仕様確定](#phase-2) | 部分成功時の保存単位と再実行条件を確定 [R1] | 保存済みの行と未保存の行を、画面・再実行・出力で同じ基準で区別できるか |
| Phase 3 CSV受付 | 登録前の内容確認を整備 | 利用者が確認したデータと検証・登録するデータが一致するか |
| Phase 4 全行検証 | CSVの全行を検証 | 複数の不正行を報告し、問題があれば登録を開始しないか |
| [Phase 5 一括登録](#phase-5) | 検証済みデータを登録 | 未検証の入力や検証後の競合が制約をすり抜けないか |
| [Phase 5 一括登録](#phase-5) | 未保存の行だけを再実行できるようにする [R1] | 再実行しても保存済みの行が二重登録されないか |
| [Phase 5 一括登録](#phase-5) | 失敗した行をCSVで出力する [R2] | 出力した行を修正して再投入すると、未保存の行だけが登録されるか |
| [Phase 6 接続・統合検証](#phase-6) | 管理画面の利用経路へ接続 | 受付から結果表示までつながり、エラーが利用者へ届くか |
| [Phase 6 接続・統合検証](#phase-6) | 一括登録を通しで検証 | 途中失敗後の保存状態、再実行、失敗行の出力が画面表示と一致するか [R1][R2] |
| [Phase 6 接続・統合検証](#phase-6) | 既存の登録経路を再検証 | 単件登録や編集に回帰影響がないか |
| [Phase 7 導入・運用](#phase-7) | 一部の管理者へ先行公開する [R3] | 先行公開中の問題を検知し、停止・切り戻しできるか |
| [Phase 7 導入・運用](#phase-7) | 全体へ公開する [R3] | 先行公開での確認を終えてから広げるか |
| [Phase 7 導入・運用](#phase-7) | 運用担当へ引き継ぐ | エラー対応と再実行を担当者が判断できるか |
| [Phase 7 導入・運用](#phase-7) | 確認用資産を撤去 | 本番確認完了後に不要物を撤去できるか |

### 0.3 要注意事項・人間判断

- **決定済み [R1]:** 登録実行中の失敗は部分成功とし、保存済みの行を残す。全行事前検証と不正入力時の登録0件は維持する。
- **AIが調査:** 既存の重複制約と処理上限をPhase 1で調べ、Phase 2で重複の扱いと最大行数を確定する。根拠資料の確認は未実施。
- **導入前に決定 [R3]:** 先行公開する管理者の範囲、全体公開へ進む条件、停止判断の担当者をPhase 7着手前に決める。

### 0.4 重要な依存・分岐

- Phase 1 → Phase 2 → Phase 3・4・5 → Phase 6 → Phase 7。Phase 3・4・5は共通仕様の確定後に並行できる。
- 入力不正なら登録開始前に終了する。登録実行中の失敗では保存済みの行を残し、未保存の行と失敗理由を利用者へ示す [R1][R2]。
- 先行公開で問題がないことを確かめてから全体へ公開する [R3]。本番確認が終わるまで、復旧に必要な資産を撤去しない。

# Phase 2

**仕様確定**

1. CSV項目、空値、形式、重複、最大行数を決め、正常例と不正例を用意する。
2. 部分成功の方針に沿って、保存単位（1行ごと）と、保存済み・未保存・失敗理由の記録方法を決める [R1]。
3. 再実行の対象にする行と、失敗行の出力に含める項目をPhase 5・6へ渡す [R1][R2]。

- 確認事項: 保存済みの行と未保存の行を、画面表示・再実行・出力で同じ基準で区別できるか [R1][R2]。
- 完了条件: 方針と各ケースの期待結果を記録し、Phase 5の実装に必要な条件を説明できる。

# Phase 5

**一括登録**

開始条件: Phase 2で保存単位、重複、再実行の仕様が確定していること。

1. 検証済みデータを行単位で保存し、検証後の競合も保存時の制約で防ぐ [R1]。
2. 再実行では未保存の行だけを登録し、保存済みの行は重複判定で除外する [R1]。
3. 失敗した行と理由をCSVで出力し、修正して再投入できるようにする [R2]。

- 確認事項・完了条件: 100行中60行の保存後に失敗し、同じ操作で再実行すると、残りの40行だけが登録されて合計100件になる [R1]。出力した失敗行を修正して再投入しても、保存済みの行は増えない [R2]。

# Phase 6

**接続・統合検証**

1. 受付、検証、登録、結果表示、失敗行の出力を管理画面へ接続する [R2]。
2. 正常、不正入力、途中失敗、再実行、失敗行の再投入、検証後の競合を入口から試す [R1][R2]。
3. Phase 1で特定した既存の登録・編集経路を再検証する。

- 確認事項・完了条件: 画面表示、出力、実際の保存状態が一致し、既存経路の期待結果も維持される [R1][R2]。検証結果は未取得。

# Phase 7

**導入・運用**

1. 先行公開する範囲、全体公開へ進む条件、停止担当者を決め、停止・切り戻し・データ復旧後の確認手順を用意する [R3]。
2. 一部の管理者へ先行公開し、登録結果と問い合わせを確認する [R3]。
3. 先行公開での確認を終えてから全体へ公開し、障害対応と再実行の手順を運用担当へ渡す [R3]。
4. 本番確認の完了後に確認用資産を撤去する。

- 確認事項・完了条件: 先行公開中に問題が出たら公開範囲を戻し、保存済みの行を確認できる [R3]。コードの切り戻しだけで登録済みデータが戻ると仮定しない。
