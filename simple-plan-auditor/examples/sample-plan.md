# CSV一括登録機能 実装計画

この計画は説明用のデモ。以下の根拠資料名・確認方法は記載例であり、実在資料の確認や動作検証は行っていない。

## 0. 全体概要

### 0.1 目的

管理画面からCSVの全行を事前検証し、不正データが1件でもあればCSVによる登録を0件に保つ。利用者が問題行を修正して再実行できる顧客一括登録機能を作る。

### 0.2 全体作業マップ

| 工程 | 主な作業 | 確認事項 |
|---|---|---|
| [Phase 1 現行把握](#phase-1) | 現行の登録経路を整理 | 管理画面以外の登録経路と共有処理も把握できているか |
| [Phase 1 現行把握](#phase-1) | 既存のデータ制約を整理 | 必須項目や重複条件を新経路でも維持できるか |
| [Phase 2 仕様確定](#phase-2) | 入力条件を確定 | CSV内重複と既存顧客重複を含む全行検証の条件が明確か |
| [Phase 2 仕様確定](#phase-2) | 途中失敗時の扱いを決定 | 成功単位と再実行条件を登録実装前に決められるか |
| [Phase 3 CSV受付](#phase-3) | 登録前の内容確認を整備 | 利用者が確認したデータと検証・登録するデータが一致するか |
| [Phase 4 全行検証](#phase-4) | CSVの全行を検証 | 複数の不正行を報告し、問題があれば登録を開始しないか |
| [Phase 5 一括登録](#phase-5) | 検証済みデータを登録 | 未検証の入力や検証後の競合が制約をすり抜けないか |
| [Phase 5 一括登録](#phase-5) | 途中失敗からの再実行を整備 | 決定した成功単位を守り、意図しない二重登録を防げるか |
| [Phase 6 接続・統合検証](#phase-6) | 管理画面の利用経路へ接続 | 受付から結果表示までつながり、エラーが利用者へ届くか |
| [Phase 6 接続・統合検証](#phase-6) | 一括登録を通しで検証 | 正常時と途中失敗後の保存状態が画面表示と一致するか |
| [Phase 6 接続・統合検証](#phase-6) | 既存の登録経路を再検証 | 単件登録や編集に回帰影響がないか |
| [Phase 7 導入・運用](#phase-7) | 本番導入を実施 | 停止条件と切り戻し後のデータ確認方法が準備できているか |
| [Phase 7 導入・運用](#phase-7) | 運用担当へ引き継ぐ | エラー対応と再実行を担当者が判断できるか |
| [Phase 7 導入・運用](#phase-7) | 確認用資産を撤去 | 本番確認完了後に不要物を撤去できるか |

### 0.3 要注意事項・人間判断

- **Phase 2で決定:** 登録実行中の失敗を全件取消にするか、部分成功を許可するか。Phase 5の登録実装は決定を待つが、Phase 1の調査は進められる。全行事前検証と不正入力時の登録0件は、どちらでも維持する。
- **AIが調査:** 既存の重複制約と処理上限をPhase 1で調べ、Phase 2で重複の扱いと最大行数を確定する。根拠資料の確認は未実施。
- **導入前に決定:** 初回公開範囲と停止判断の担当者をPhase 7着手前に決める。

### 0.4 重要な依存・分岐

- Phase 1 → Phase 2 → Phase 3・4・5 → Phase 6 → Phase 7。Phase 3・4・5は共通仕様の確定後に並行できる。
- 入力不正なら登録開始前に終了する。検証後の競合や登録実行中の失敗はPhase 2の成功単位に従い、Phase 5・6・7へ反映する。
- 本番確認が終わるまで、復旧に必要な資産を撤去しない。

# Phase 1

**現行把握**

1. 管理画面と他の呼び出し元から、保存処理・共有処理まで登録経路を追う。
2. 必須項目、重複制約、保存時処理、処理上限を調べ、変更対象と回帰確認対象をPhase 2へ渡す。

- 確認事項: 新経路で維持すべき制約と、既存経路への影響を把握できたか。
- 根拠候補: 添付「顧客管理仕様」第3章、登録処理と既存テスト。いずれもデモ上は未確認。
- 確認方法・完了条件: 資料と処理を照合し、制約の出典と未確認点を説明できる。

# Phase 2

**仕様確定**

1. CSV項目、空値、形式、重複、最大行数を決め、正常例と不正例を用意する。
2. 100行中60行の保存後に失敗した場合を人間に示し、全件取消または部分成功を選ぶ。
3. 選んだ方針の保存状態、表示、復旧、再実行の期待結果をPhase 5・6・7へ渡す。

- 確認事項: 不正入力時の登録0件と、実行中の障害に対する成功単位を混同していないか。
- 完了条件: 方針を記録し、登録実装に必要な各ケースの期待結果を説明できる。現在は未決定。

# Phase 3

**CSV受付**

1. 空・形式不正・読込不能なファイルを拒否し、正常ファイルの件数と内容を表示する。
2. 確認したデータをPhase 4へ渡し、取消時は登録を開始しない。

- 確認事項・完了条件: 確認対象と検証対象が一致し、不正ファイルや取消操作で顧客データが変わらない。

# Phase 4

**全行検証**

1. 全行の必須値、形式、CSV内重複、既存データとの競合を検証し、行番号と理由を返す。
2. 不正や検証処理の失敗があれば登録へ進ませず、成功したデータだけをPhase 5へ渡す。

- 確認事項: 最終行まで問題を確認でき、不正が1件でもあれば登録0件を維持するか。
- 確認方法: [Task 4.1](#task-41) の操作で確認する。完了条件は各入力条件の期待結果を満たすこと。

## Task 4.1

**不正入力で登録を開始しない**

- 前提・対象: デモ用の隔離された顧客データと10行のCSV。2行目と10行目に異なる不正値を入れ、開始前の登録件数を記録する。
- 操作: 管理画面からCSVを選択して検証する。次に両行を修正して再検証する。
- 期待結果: 最初は両行の番号と理由が表示され、登録処理が始まらず件数も変わらない。修正後は検証を通過するが、登録操作までは件数が変わらない。
- 結果・証拠: 未実施。実施後にテスト結果と開始前後の件数を添付する。

# Phase 5

**一括登録**

開始条件: Phase 2で成功単位、重複、再実行の仕様が確定していること。

1. 検証済みデータを保存し、検証後の競合も保存時の制約で防ぐ。
2. 途中失敗の保存状態と再実行を仕様に合わせ、成功件数・失敗内容・最終状態を画面へ返す。

- 確認事項・完了条件: 未検証入力が保存されず、60行保存後の失敗と同じ操作の再実行で、保存件数がPhase 2の期待結果に一致する。

# Phase 6

**接続・統合検証**

1. 受付、検証、登録、結果表示を管理画面へ接続する。
2. 正常、不正入力、途中失敗、再実行、検証後の競合を入口から試す。
3. Phase 1で特定した既存の登録・編集経路を再検証する。

- 確認事項・完了条件: 画面表示と実際の保存状態が一致し、問題時に次の操作を判断でき、既存経路の期待結果も維持される。検証結果は未取得。

# Phase 7

**導入・運用**

1. 公開範囲と停止担当者を決め、停止・切り戻し・データ復旧後の確認手順を用意する。
2. 本番へ反映して初回確認し、障害対応と再実行の手順を運用担当へ渡す。
3. 初回確認の完了後に確認用資産を撤去する。

- 確認事項・完了条件: コードの切り戻しだけで登録済みデータが戻ると仮定せず、Phase 2の成功単位に沿って復旧できる。運用担当への引き継ぎと不要物の撤去まで確認する。
