# CSV一括登録機能 実装計画

## 0. 全体概要

### 0.1 目的

管理画面からCSVを取り込み、登録内容を事前検証したうえで顧客データを一括登録できるようにする。

不正データが含まれる場合は登録を開始せず、利用者が問題箇所を特定して修正・再実行できる状態を実現する。

### 0.2 全体作業マップ

| 工程 | 主な作業 | 確認事項 |
|---|---|---|
| **現行把握・影響分析** | 現行の顧客登録フローを整理 | 管理画面以外を含め、見落としている登録経路がないか |
| **現行把握・影響分析** | 関連処理と依存先を整理 | CSV追加によって影響する呼び出し元・共有処理・外部依存を網羅しているか |
| **現行把握・影響分析** | 既存データ制約を整理 | 必須項目・重複条件・保存時処理を新経路でも維持する必要がないか |
| **登録仕様・判断事項の確定** | CSVで受け付ける項目を確定 | 既存登録項目との対応に欠落や意味の不一致がないか |
| **登録仕様・判断事項の確定** | 重複データの扱いを確定 | エラー・スキップ・更新の選択が再実行時の挙動と矛盾しないか |
| **登録仕様・判断事項の確定** | 一括登録の成功単位を確定 | 全件成功と部分成功のどちらを採るか曖昧なまま登録処理へ進まないか |
| **CSV受付・内容確認** | CSV受付を整備 | 空ファイル・対象外形式・読込不能ファイルを後続へ流さないか |
| **CSV受付・内容確認** | 登録前の内容確認を整備 | 利用者が確認した内容と実際に検証・登録される内容が一致するか |
| **全行検証** | 全行を登録条件に照らして検証 | 最初のエラーで打ち切らず、必要な問題を全件確認できるか |
| **全行検証** | 検証結果を利用者へ返す | 行番号と理由が修正可能な粒度で示され、問題がある状態で登録へ進まないか |
| **一括登録** | 検証済みデータを一括登録 | 検証を通過していないデータが登録経路へ入らないか |
| **一括登録** | 途中失敗時の状態を確定 | 許容しない部分登録や中間状態が残らないか |
| **一括登録** | 再実行・重複実行の扱いを適用 | 同じ操作の再実行で意図しない二重登録が発生しないか |
| **管理画面への組み込み** | CSV選択から登録結果までを実利用経路へ接続 | 個別に実装した処理が接続漏れなく利用経路から到達可能か |
| **管理画面への組み込み** | 検証・登録エラーを画面へ返す | エラーが途中で失われず、利用者が次の操作を判断できるか |
| **統合・回帰検証** | 正常フローを通しで検証 | CSV選択から登録結果まで期待する最終状態へ到達するか |
| **統合・回帰検証** | 異常・途中失敗・再実行を検証 | 問題発生時に誤登録や不整合が残らず、再実行可能な状態へ戻るか |
| **統合・回帰検証** | 既存の単件登録・編集を再検証 | CSV機能追加によって従来経路へ回帰影響がないか |
| **本番導入・復旧準備** | 本番導入手順を確定 | 導入前提と初回確認項目が明確か |
| **本番導入・復旧準備** | 停止・切り戻し手順を確定 | 問題発生時に安全な状態へ復旧できるか |
| **運用移管・旧資産撤去** | 利用・障害対応手順を更新 | 運用担当がエラー対応と再実行方法を判断できるか |
| **運用移管・旧資産撤去** | 暫定設定・確認用資産を撤去 | 本番確認より先に撤去せず、不要物を残したまま終了しないか |

### 0.3 要注意事項・人間判断

- 🔴 **既存メールアドレスとの重複時の扱いが未決定。** エラー、スキップ、更新のいずれかで登録処理・再実行条件が変わる。
- 🔴 **部分成功を許可するか未決定。** 全件一括成功を前提とするか、行単位成功を許容するかで復旧設計が変わる。
- 🟡 **最大行数が未決定。** 大量データ時の確認条件と導入時の制約が確定していない。
- 🟡 **初回導入時に限定公開するか人間判断が必要。** 導入手順と初回確認範囲に影響する。

### 0.4 重要な依存・分岐

```text
現行把握・影響分析
        ↓
登録仕様・判断事項の確定
        ↓
CSV受付・内容確認 ─────┐
        ↓              │
全行検証               │
        ↓              │
一括登録 ──────────────┤
                       ↓
               管理画面への組み込み
                       ↓
                 統合・回帰検証
                       ↓
                本番導入・復旧準備
                       ↓
               運用移管・旧資産撤去
```

- 重複時の扱いが確定するまで、一括登録の最終仕様を確定しない。
- CSV受付と登録処理は、共通仕様確定後であれば一部並行して実装できる。
- 統合検証は管理画面への組み込み完了後に実施する。
- 旧資産の撤去は本番導入と初回確認の完了後に行う。

# Phase 1: 現行把握・影響分析

## 目的

CSV登録を追加する前提として、現在の顧客登録フロー、依存関係、変更影響を整理する。

## 前提・開始条件

なし。

## 作業手順

1. 管理画面から既存の単件登録を実行し、利用フローを確認する。
2. 画面から登録完了までの処理経路を追跡する。
3. 顧客データの必須項目、重複判定、保存時の共通処理を整理する。
4. 呼び出し元、関連画面、共有データ、既存テストを洗い出す。
5. CSV登録で再利用可能な処理と、新規に必要な処理を区別する。
6. 変更影響と未決定事項をPhase 2へ引き渡す。

## 次工程へ渡すもの

- 現行フロー
- 変更影響一覧
- 再利用可能な処理一覧
- 未決定事項一覧

## 確認事項

- [ ] 管理画面以外の登録経路が存在しないか確認した
- [ ] 既存データへ適用されている制約を把握した
- [ ] CSV登録で再利用する処理と独自実装する処理を区別した
- [ ] 変更対象外だが回帰確認が必要な経路を特定した

## 完了条件

変更対象、再利用対象、回帰確認対象、未決定事項を説明できる。

---

# Phase 2: 登録仕様・判断事項の確定

## 目的

CSV受付から登録結果まで一貫して使用する業務ルールを確定する。

## 前提・開始条件

Phase 1の現行仕様と変更影響が整理済みであること。

## 作業手順

1. CSVの必須列・任意列を確定する。
2. 値の形式、不正値、空値の扱いを確定する。
3. CSV内重複と既存顧客重複の扱いを確定する。
4. 全件一括成功か部分成功かを確定する。
5. 再実行時の期待結果を定義する。
6. ファイルサイズ・行数の上限を確定する。
7. 正常例と代表的な異常例を用意する。

## 確認事項

- [ ] 同じルールを受付、検証、登録、結果表示で一貫して利用できる
- [ ] 重複・再実行・部分失敗の扱いに矛盾がない
- [ ] 実装者が判断を補完しなくても期待結果を説明できる

## 完了条件

主要な入力パターンについて、登録可否と期待結果を実装前に説明できる。

---

# Phase 3: CSV受付・内容確認

## 目的

利用者がCSVを指定し、登録前に内容を確認できる入口を整備する。

## 作業手順

1. CSV受付を管理画面へ追加する。
2. 対象外形式、空ファイル、読込不能ファイルを受付段階で判定する。
3. CSVを解析し、Phase 2で定義した列構造へ変換する。
4. 件数と主要項目を登録前に確認できる状態にする。
5. 受付結果を全行検証へ引き渡す。

## 分岐・例外

- ファイル自体が処理不能な場合は全行検証へ進めない。
- 内容確認で利用者が取り消した場合は登録処理を開始しない。

## 確認事項

- [ ] 基本形式エラーを後続工程へ流さない
- [ ] 登録前のデータと実際に検証されるデータが一致する
- [ ] キャンセル時に副作用が発生しない

## 完了条件

正常CSVを全行検証へ渡せ、不正ファイルは登録処理へ到達しない。

---

# Phase 4: 全行検証

## 目的

登録開始前にCSV全体を検証し、問題がある場合は修正可能な情報を利用者へ返す。

## 作業手順

1. 全行を走査する。
2. 必須値と値形式を検証する。
3. CSV内の重複を検出する。
4. 既存データとの競合を検証する。
5. 行番号、項目、理由を含む問題一覧を生成する。
6. 問題が0件の場合のみ登録可能状態へ遷移する。

## 分岐・例外

- 一件の不正で検証全体を打ち切らない。
- 検証中にシステムエラーが発生した場合は登録可能状態へ遷移しない。

## 確認事項

- [ ] 最終行まで検証する
- [ ] 複数の問題を一度に確認できる
- [ ] 問題が存在する状態で登録へ進まない
- [ ] 修正後に同じCSVを再検証できる
- [ ] 検証結果と登録時ルールが乖離しない

## 完了条件

複数の問題を含むCSVで、データ登録を行わず問題一覧を返せる。

---

# Phase 5: 一括登録

## 目的

検証済みデータを定義済みの一括処理方針に従って登録し、失敗・再実行時にも整合性を維持する。

## 作業手順

1. 検証済みデータのみ受け付ける。
2. Phase 2で確定した登録単位に従って登録する。
3. 途中失敗時の状態を確定する。
4. 再実行・二重実行時の重複防止を適用する。
5. 成功件数、失敗内容、最終状態を返す。

## 確認事項

- [ ] 検証を通過していないデータを登録できない
- [ ] 途中失敗時に許容されない部分登録が残らない
- [ ] 同じ操作の再実行結果が定義どおりになる
- [ ] 登録結果と実際の保存状態が一致する

## 完了条件

正常登録、途中失敗、再実行の各条件で、期待する最終状態を確認できる。

---

# Phase 6: 管理画面への組み込み・統合検証

## 目的

実装済みの各処理を既存管理画面の利用フローへ組み込み、入口から結果表示までを検証する。

## 作業手順

1. CSV選択から受付処理へ接続する。
2. 内容確認から全行検証へ接続する。
3. 検証成功時のみ一括登録へ進む。
4. 検証エラー・登録エラーを管理画面へ返す。
5. 正常フローを入口から結果表示まで実行する。
6. 不正入力、途中失敗、再実行を実行する。
7. 既存の単件登録・編集を再検証する。

## 確認事項

- [ ] 個別実装がすべて実利用経路へ接続されている
- [ ] エラー原因が利用者の操作地点まで戻る
- [ ] 正常系と異常系で画面状態が矛盾しない
- [ ] 既存登録機能へ回帰影響がない
- [ ] 目的に沿った最終状態を統合状態で確認できる

## 完了条件

管理画面から代表的な正常・異常・再実行ケースを通しで実行し、期待結果を確認できる。

---

# Phase 7: 本番導入・運用移管・旧資産撤去

## 目的

新機能を本番利用可能な状態へ移行し、問題発生時の復旧経路を確保したうえで、暫定対応を撤去して作業を完了する。

## 作業手順

1. 本番導入前提条件を確認する。
2. 導入手順と初回確認項目を確定する。
3. 停止条件と切り戻し手順を確定する。
4. 本番へ反映する。
5. 正常CSVを使用して初回動作を確認する。
6. 管理者向けCSV仕様、エラー対応、再実行方法を更新する。
7. 実装中だけ使用したログ、フラグ、設定、確認用資産を撤去する。
8. 完了条件を再確認し、残課題を記録する。

## 確認事項

- [ ] 切替直後に問題を検知できる
- [ ] 問題時に機能停止または切り戻しが可能である
- [ ] 切り戻し後の確認手順がある
- [ ] 暫定資産の撤去が本番確認より先行しない
- [ ] 運用担当が利用・障害対応方法を把握できる
- [ ] 未解決事項を完了扱いで隠していない

## 完了条件

本番で利用可能であり、切り戻し・運用・文書化・旧資産撤去を含む完了条件をすべて満たしている。

**問題:** 既存メールアドレスを含む行について、エラー・スキップ・更新のいずれを採用するか未決定。

**必要な理由:** 途中失敗時の最終状態、復旧、再実行方法が変わる。

**追加・修正先:** Phase 2で方針を確定し、Phase 5・6・7へ反映する。
