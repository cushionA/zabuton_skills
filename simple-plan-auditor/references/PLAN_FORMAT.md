# Plan出力フォーマット

このテンプレートは固定様式ではない。目的は、読者が **L0 → L1 → L2** の順に必要な深さまで降りられ、L0だけで作業全体と重要な確認事項を把握できる状態を作ることにある。

# L0: 全体概要

```markdown
# <計画名>

## 0. 全体概要

### 0.1 目的
<作業完了後に何が可能になるか、何が変わるか>

### 0.2 全体作業マップ

| 工程 | 主な作業 | 確認事項 |
|---|---|---|
| 現行把握・影響分析 | 現行の利用フローを整理 | 見落としている利用経路がないか |
| 現行把握・影響分析 | 関連する依存先を整理 | 暗黙の依存関係が残っていないか |
| ... | ... | ... |

### 0.3 要注意事項・人間判断
- 🔴 ...
- 🟡 ...
- 判断事項がなければ `なし`

### 0.4 重要な依存・分岐
- ...
- 特記すべき依存・分岐がなければ `なし`
```

`0.4 重要な依存・分岐` は全体概要の最後に置く。

## 全体作業マップの原則

### 主な作業は1行1作業

1つの表行に複数の作業を詰め込まない。

良い例:

```markdown
| 現行把握・影響分析 | 現行の利用フローを整理 | 見落としている利用経路がないか |
| 現行把握・影響分析 | 依存先と共有データを整理 | 暗黙の依存関係が残っていないか |
```

避ける例:

```markdown
| 現行把握・影響分析 | 現行フロー / 依存先 / 共有データ / 変更影響を整理 | ... |
```

工程名は一意である必要はない。同じ工程に属する複数の作業は、工程名を繰り返してよい。

### 確認事項を主役にする

この表の主目的は、実装内容を説明することではなく、**作業の抜け・順序の誤り・成立条件の見落としに人間が気づけるようにすること**である。

そのため、確認事項は技術的な細部ではなく、次のような論理条件を優先する。

- 前提が確定しているか
- 必要な作業が後続工程へ正しく接続されるか
- 分岐ごとの扱いが定義されているか
- 一部成功・途中失敗で不整合が残らないか
- 再実行・重複実行で結果が崩れないか
- 既存経路への影響が確認されるか
- 移行・切替・切り戻しの順序が成立しているか
- 最終状態に不要な旧資産や暫定対応が残らないか

論理的に確認すべき事項は、表を短くするために削除してはならない。

### 確認事項がない場合

空欄にしない。明示的に `なし` と記載する。

これは「確認漏れ」と「確認した結果、特記事項がない」を区別するためである。

### 大規模計画の粒度

L0が大きくなりすぎる場合、複数作業を1セルへ詰め込まず、**L0へ載せる作業自体の抽象度を一段上げる**。

たとえば、L1では

```text
ファイル受付
形式確認
内容読込
プレビュー生成
```

と分かれていても、L0では

```text
入力受付を整備
登録前確認を整備
```

のように上位作業へまとめてよい。

ただし、独立して確認すべき重要な分岐・移行・切替・復旧・高リスク作業まで埋没させてはならない。

# L1: 工程詳細

```markdown
# Phase N: <工程名>

## 目的
<この工程で達成する状態>

## 前提・開始条件
- ...
- 特記事項がなければ `なし`

## 作業手順
1. ...
2. ...
3. ...

## 分岐・例外
- ...
- 特記事項がなければ `なし`

## 次工程へ渡すもの
- ...

## 確認事項
- [ ] ...
- [ ] ...
- 特記事項がなければ `なし`

## 完了条件
<この工程を完了と判断できる状態>

## 詳細Task
...
```

完了条件はL1へ置く。L0には独立した完了条件セクションを置かない。目的達成に必要な最終確認は、全体作業マップの確認事項へ織り込む。

低リスク工程では不要な節を省略してよい。ただし、節を残す場合は空欄にせず `なし` と明示する。確認事項の有無は曖昧にしない。

# L2: Task詳細

```markdown
### Task N.M: <名称>

**Before**
- 事前確認

**Action**
- 実施内容

**Touch**
- 変更・確認対象

**Connect**
- 他工程・既存経路との接続

**Verify**
- 検証方法
```

必要な項目だけ使用する。

# Plan Review Summary

監査結果はPlan全文を再説明せず、問題箇所へ直接誘導する。

```markdown
# Plan Review

## Result
PASS / NEEDS REVISION

## BLOCKERS
### Phase N — <短い題名>
問題:
必要な理由:
追加・修正先:

## WARNINGS
...

## MISSING WORK
- ...

## ORDER / DEPENDENCY ISSUES
- ...

## UNVERIFIED CONDITIONS
- ...

## HIDDEN ASSUMPTIONS
- ...

## HUMAN DECISIONS REQUIRED
- ...
```
