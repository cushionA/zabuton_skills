# 必要なもの（入力パターン別）

資料の作り方は「画面をどう用意するか」で5パターンに分かれる。どのパターンでも **データレイアウト** と **操作シナリオ（何をする手順か）** は共通で必要。

## 早見表

| | A. 起点URL＋操作シナリオ | B. URLの流れ | C. 手持ちの画面キャプチャ | D. 既存の Playwright コード |
|---|---|---|---|---|
| 用意するもの | 起点URL<br>操作内容（文章でよい） | 画面ごとのURL（遷移順）<br>各画面での操作 | 画面キャプチャ（遷移順）<br>各画像での操作 | 操作を書いたスクリプト<br>（取得値の対応が分かるもの） |
| 共通で必要 | データレイアウト | データレイアウト | データレイアウト | データレイアウト |
| 向いているケース | ログイン不要の公開サイト（第一候補） | 自動操作の再現が難しいが、各画面にURLで直接行ける／開く商品を固定したい | ログイン必須・社内システム・自動アクセスできないサイト／特定時点の画面を残したい | 実際のクローラーや codegen で作った操作手順がある |
| 撮影 | Claude がブラウザを操作して撮る | Claude が各URLを開いて撮る | 用意した画像をそのまま使う | コードと同じ操作・ロケータで Claude が撮る |
| 赤枠の位置 | 画面要素の座標から自動配置（正確） | 同左（正確） | 画像を見て座標を読み取る（数px〜十数pxずれることがある。PowerPointで微調整する前提） | 同 A（正確） |
| サイト改修後の撮り直し | シナリオを再実行するだけ | 同左（URLが変わればURLを差し替え） | 画像を撮り直してもらう | 同 A |

迷ったら A。A で弾かれる画面（ログイン・CAPTCHA・地域制限など）だけ C に切り替える混在もできる。

実行済みテストの結果を使う **E（Playwright JSONレポート＋添付PNG）** は[実行結果のインポート](import-results.md)を参照。ログイン後の画面も、保存済み画像として利用できる。画像候補と利用範囲を確認し、再ログイン・再撮影せず資料化する。赤枠は C と同じく画像から読み取る。

## 共通: データレイアウト

納品データの定義表。Excel・CSV・チャットへの表貼り付けのどれでもよい。

| 列 | 必須 | 内容 |
|---|---|---|
| No. | 必須 | 項目番号。データ取得スライドの赤枠番号はこの番号になる（例: No.3 商品名 → ③） |
| 項目名 | 必須 | 例: 商品名 |
| 型 | 必須 | 例: 文字列 / 数値 / 日時（表記は納品仕様のまま使う） |
| 画面から取らない項目か | 必須 | クロール日時・アクセスURLなど、画面上に表示がない項目がどれか。スライドではグレーアウトする |
| 備考 | 任意 | 例: 税込価格。最後の「取得項目と取得元の対応」スライドに載る |
| 取得元の説明 | 任意 | 画面から取らない項目の出どころ（例: クロール実行時に付与） |

画面上のどこが各項目に当たるかが自明でない場合は一言添えてもらう（例: 「ポイントは価格の下の"○○ポイント"の数値」）。

## A. 起点URL＋操作シナリオ

用意するもの:

- 起点URL（例: `https://wowma.jp/`）
- 操作シナリオ。文章でよいが、次が分かるようにする
  - 入力する値（検索キーワードなど）
  - 絞り込み・並び替えの条件（例: ショップ「コジマ au PAY マーケット店」で絞り込む）
  - どの結果を開くか（例: 一覧の1件目を例として開く）
  - 取得の範囲（例: 一覧の全商品について繰り返す）。スライドには補足として書く
- データレイアウト

例（au PAY マーケット）: 「トップでワイヤレスイヤホンを検索 → 左メニューのショップでコジマに絞り込み → 1件目の商品詳細で商品名・価格・ポイントを取る」

## B. URLの流れ

用意するもの:

- 画面ごとのURLを遷移順に並べたもの

  ```
  1. トップ          https://wowma.jp/
  2. 検索結果        https://wowma.jp/itemlist?keyword=ワイヤレスイヤホン
  3. 絞り込み後      https://wowma.jp/itemlist?keyword=ワイヤレスイヤホン&user=43478324
  4. 商品詳細        https://wowma.jp/item/706060336
  ```

- 各画面で何をするか（A と同じ粒度）
- データレイアウト

注意: セッションIDや一時トークンを含むURLは時間が経つと開けない。ログイン後でないと開けないURLは C にする。

## C. 手持ちの画面キャプチャ

用意するもの:

- 画面キャプチャ（遷移順に番号を付けたファイル名、PNG推奨）
- 各画像で何をするか・何を取るか
- データレイアウト
- 画面の拡大率（Windows の表示スケール 100% / 125% / 150% など。分からなければ「不明」で可）
- 元ページのURL（任意。顧客が開けるページならリンクを付ける）

撮り方のお願い:

- ブラウザの表示倍率は 100%、ウィンドウ幅は 1280〜1600px 程度
- ページの表示領域だけを撮る（アドレスバー・タスクバー・他のウィンドウは入れない）
- 赤枠を付けたい要素が画像の中に全部入るようにする（取得項目が縦に離れているなら、範囲ごとに分けて撮ってよい）
- ポップアップやサジェストが重なっていない状態で撮る
- 個人情報・ログインIDなどが写らないようにする

C の赤枠は Claude が画像を見て座標を決めるため、A/B より位置精度が落ちる。赤枠は PowerPoint で編集できるので、細かなずれは納品前に PowerPoint 上で直す。

## D. 既存の Playwright コード

用意するもの:

- 操作を書いたスクリプト（Python / Node どちらでも。`playwright codegen` の出力でもよい）
- 取得した値がデータレイアウトのどの項目になるか（辞書のキーや変数名が項目名と対応していれば不要）
- データレイアウト

コードの `goto` / `fill` / `click` / 値の読み取りから撮影案を整理し、ユーザーと合意した範囲を画面ごとの手順に写す。ロケータ（`get_by_role` など）は書き換えずにそのまま使う。コードの受領だけで全分岐・全商品を撮影しない。

- ループで全件を処理している部分は、代表1件での例示を提案し、合意後に撮る。「各商品について繰り返す」と補足する
- ログイン処理（パスワード入力）は Claude が実行しない。ログイン後の画面は C として画像をもらう

## 表示の違い（商品によって表示が変わる場合）

存在する表示差分の一覧と、今回の資料に含める表示差分を分ける。ユーザーが選んだものだけ撮影し、コードやサイトで見つけた差分を自動追加しない。

用意するもの:

- その表示が出ているページのリンク（ログインが必要なページなら画像）
- どこが違うか、取得ではどう扱うか（例: 「レビューが無い商品は評価欄が出ない。レビュー件数は0とする」）

扱いは2通り。

- **小さな違い**: 該当ブロックだけを切り抜き、取得スライドの右側に小さく添える（「表示が異なる場合」）
- **取得位置が変わる違い**: 専用スライドにして「通常表示との違い」を書く

## 既存の資料に差し込む場合

用意するもの:

- 差し込み先の pptx（提案書など）
- 差し込む位置（何枚目の後か）

生成の前に差し込み先をプレビューし、差し込み位置の前後のデザインを確認する（手順は SKILL.md の「4. 生成する」）。差し込み先のタイトル書式・本文領域・テーマ色・フォント・フッターに合わせて作る。表紙は作らない。元のファイルは上書きせず、別名で出力する。

## 不足しているときの確認テンプレート

一度にまとめて聞く。分かっている項目は聞かない。

```
資料作成にあたり、以下を教えてください。
1. 画面の用意方法: (A) 起点URLから自動で撮る / (B) 画面ごとのURLを指定する / (C) 撮影済みの画像を使う / (D) 既存のPlaywrightコードを使う / (E) Playwrightの実行結果を取り込む
2. 起点URL（A）、画面ごとのURL（B）、画像（C）、コード（D）、またはJSONレポートと添付PNG（E）
3. 操作の流れ: 入力する値、絞り込み条件、どの結果を開くか、全件繰り返すか
4. データレイアウト（No.・項目名・型、画面から取らない項目はどれか）
5. 今回の資料に含めたい表示の違いがあれば、その例のページと扱い方（全パターンの用意は不要）
6. 既存の資料に差し込む場合は、その pptx と差し込む位置
7. 資料タイトル（省略時は「<サイト名> <取得内容>取得手順」）
```

## 撮影範囲の確認例

受け取った資料だけで案を具体化し、不足情報の確認と一緒に提示する。対象がすでに指定・合意済みなら、重ねて確認しない。

```
撮影案は次のとおりです。
- 検索結果と絞り込み結果：操作順を示す2画面
- 商品詳細：代表1商品の商品名・価格・ポイントを示す1画面
- 表示の違い：今回はセール表示1件だけ追加
- 手持ち画像：トップ画面は再利用
- 対象外：全商品の巡回、レビューなし・売り切れの追加撮影
新規撮影は4枚の予定です。読みやすく分割する場合、スライド数はこれより増えます。
この範囲で進めてよいですか。追加・除外する画面があれば教えてください。
```
