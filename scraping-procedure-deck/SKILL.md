# Scraping Procedure Deck

## 成果物

16:9 の .pptx を1つ作る。構成は次の4つ。

1. 表紙（タイトル・対象サイト・取得項目数・作成日）
2. 全体の流れ（画面サムネイル＋矢印。各画面で何をするかの一文と、資料の見方を添える）
3. 画面ごとのスライド（「データ取得」と「画面遷移」を別スライドに分ける）
4. 取得項目と取得元の対応（データレイアウト全項目の一覧）

- 画面キャプチャは画像として貼る。赤枠・番号・表はすべて PowerPoint のネイティブ図形にする。画像に焼き込まないので、納品後も移動・サイズ変更・番号の打ち替えができる
- 顧客向けの資料なので、セレクタ・XPath・内部IDなどの技術情報はスライドにもノートにも書かない。技術情報は scenario.json の中だけに置く
- 画面名には元ページへのリンクを付ける。URL自体は表示しない。ログインが必要なページなど、顧客が開けないページには付けない

既存の資料（提案書など）に差し込む場合は、表紙を作らない。差し込み先のレイアウト・テーマ色・フォント・フッターに合わせる。

## スライドのルール

- **レイアウト**
  - タイトルには「何をするスライドか」を書く（例: ショップで絞り込み）
  - 画像の上に区分ラベル（画面遷移／データ取得）と画面名（リンク付き）を置く
  - 左に画面キャプチャ（赤枠＋番号）、右にコンパクトな一覧を置く
    - 画面遷移: 右に「操作手順」①②…を並べ、下に「次の画面」を置く
    - データ取得: 右にデータレイアウト表（No.・項目名・型）を置く。この画面で取る行は薄赤の背景に赤字の番号にする。画面から取らない行はグレーにし、「※グレーの項目は画面から取得しない項目です」を添える
- **番号**
  - 画面遷移では、資料全体で通した操作の順番
  - データ取得では、データレイアウトの項目No.（No.3 商品名 → 赤枠も③）
  - 取得しない箇所を示すときは、点線の赤枠に ※1, ※2 を付ける
- **テーマ分け**
  - 同じ画面でもデータ取得と画面遷移は別スライドにする（取得 → 遷移の順）
  - 1スライドの赤枠は5個まで。それを超えるときや枠が縦に離れているときは、自動で（1/2）…に分割する
  - 合意した画面を読みやすく分割してよい。スライド分割のために撮影対象を増やさない
- **表示の違い**（商品によって表示が変わる場合）
  - 小さな違い（例: レビューが無ければ評価欄が出ない → 0件とする）: 別ページの該当ブロックだけを小さく切り抜き、取得スライドの右パネルに「表示が異なる場合」として添える。入りきらなければ直後に専用スライドを1枚足す
  - 取得位置が変わるほどの違い（例: メーカー希望小売価格が併記される）: 専用スライドにする。画面名の横に「表示パターン」、右パネルに「通常表示との違い」を書く

## 入力（必要なもの）

詳細とユーザーへの確認テンプレートは [references/inputs.md](references/inputs.md)。

| パターン | 用意するもの | 赤枠の位置 |
|---|---|---|
| A. 起点URL＋操作シナリオ | 起点URL、操作内容（文章でよい） | DOM座標から自動（正確） |
| B. URLの流れ | 画面ごとのURL（遷移順）、各画面での操作 | DOM座標から自動（正確） |
| C. 手持ちの画面キャプチャ | 画像（遷移順）、各画像での操作 | 画像から読み取り（要微調整） |
| D. 既存の Playwright コード | 操作を書いたスクリプト | DOM座標から自動（正確） |
| E. Playwright の実行結果 | JSONレポートと添付PNG | 保存画像から読み取り（要微調整）。サイトの再操作なし |

- どのパターンでもデータレイアウト（No.・項目名・型・画面から取らない項目）が必要
- 迷ったら A にする。ログインや CAPTCHA で自動化できない画面だけ C を混ぜる
- 表示の違いを入れるときは、その表示が出ているページのリンクと、どこが違うか（どう扱うか）をもらう
- 実行結果を渡されたら E。[実行結果のインポート](references/import-results.md)に従い、成功した実行の添付PNGを一覧化して選ぶ。通常の文字ログ・HTMLレポート・`trace.zip` の直接変換には対応しない

## ワークフロー

`S` はこの SKILL.md のあるディレクトリ。作業ディレクトリ `W` はユーザー指定の場所、無ければプロジェクト配下に作る。第三者サイトのキャプチャは公開リポジトリにコミットしない。

```
W/scenario.json   手順の定義（唯一の編集元）
W/captures/       撮影結果（PNG と deck.json）
W/out/            生成した pptx
W/preview/        目視確認用のPNG
```

### 1. 入力を確認し、撮影範囲を合意する

パターンを決め、受け取ったコード・指示・画像・データレイアウトを読む。データレイアウトが Excel/CSV なら `data_layout` に変換する。サイトを開いたりコードを実行したりする前に、次を撮影案としてまとめ、不足情報と一緒に確認する。確認文の例は inputs.md を参照。

- 撮る画面と状態、操作の流れ、各画面で示す取得項目
- 例示する商品・ページと件数、含める表示差分（レビューなし・セール等）
- 新規撮影・既存画像の再利用・撮り直しの区別、撮影枚数の目安（資料のスライド枚数とは分ける）
- 今回撮らない画面・表示差分。コード内の全件ループや条件分岐は候補であり、全件の撮影指示とは扱わない

撮影範囲が未確定なら、ユーザーの回答を待つ。回答がないまま撮影を始めない。すでに具体的な対象・表示差分・再利用範囲が指定または合意されていれば、その範囲で進め、同じ確認を繰り返さない。合意内容は作業中の会話または作業メモで参照できるようにする。

E は撮影済み画像の利用範囲と順序を合意する。レポートの受領は全添付・全リトライの採用指示ではない。画像が不足してもテストやログインを再実行せず、不足画面を伝える。

合意後に別の表示差分を見つけても自動で追加しない。追加が必要なら、その画面・理由・追加撮影枚数を提示し、追加分だけ確認する。同じ対象の待ち時間・セレクタ調整や撮影失敗のやり直しは、範囲を変えずに実施できる。

### 2. シナリオを書く

形式は [references/scenario-format.md](references/scenario-format.md)、完成例は [examples/aupay-market.json](examples/aupay-market.json)。

- **A/B**
  - Playwright（Python）で対象ページを開き、要素の場所・文言・遷移を確かめてから `target` を決める。推測で書かない
  - 1画面1 shot を基本にする。ドロップダウンを開くなどで状態が変わる場合は、状態ごとに shot を分ける
- **C**
  - `python S/scripts/overlay.py grid <画像>` で目盛り付き画像を作り、それを見て `box` の座標を読む
  - `python S/scripts/overlay.py boxes W/scenario.json` で枠を描いた確認画像を作り、ずれていれば直す
- **E**
  - `import_results.py --list` で画像候補を確認し、合意した添付IDと、画像から確認した赤枠・手順文・データレイアウトをインポート計画に書く。計画はスキル側で作成する
  - [実行結果のインポート](references/import-results.md)のコマンドで画像と `scenario.json` を生成し、撮影を飛ばして手順4へ進む。テスト名だけから操作や取得項目を決めない
- **D**
  - 合意した範囲に必要なコードの操作を、順番を保って shot と steps へ写す。対応は scenario-format.md の「Playwright コードからの変換」を参照
  - ロケータは `get_by_role` などをそのまま `target` のオブジェクト形式で書く（CSS に書き換えない）
  - ループや全件処理は合意した代表1件で例示し、`notes` に繰り返す旨を書く。先頭1件を使う案でも、範囲未確定のまま撮らない
  - コードにパスワードがある場合は、そのログイン操作を実行しない（その画面は C）

手順文（`text`）は顧客が読む文にする。画面上の文言は「」で囲む。

### 3. 撮影する（A/B/D）

`shots` と `peeks` が合意した範囲だけで構成されていることを確認して実行する。既存の scenario に他の画面が残っている場合は `--only` で限定する。選択した shot の `peeks` も撮影されるため、表示差分を全件含めたまま実行しない。`--only` でも対象へ到達するために前段の操作を再現する場合がある。

```
python S/scripts/capture.py W/scenario.json --out W/captures
python S/scripts/capture.py W/scenario.json --out W/captures --only item,item_sale   # 一部だけ撮り直す
```

- 失敗したときは `captures/_error_<id>.png` とエラーメッセージを見て、`target` や待ち時間を直す
- 撮れた PNG は必ず目で見る。確認するのは次の3点
  - ポップアップ・読み込み中表示が写り込んでいないか
  - 取得値が表示されているか
  - 意図した商品・画面か

### 4. 生成する

```
python S/scripts/build_deck.py W/scenario.json --captures W/captures -o W/out/<名前>.pptx   # A/B/D
python S/scripts/build_deck.py W/scenario.json -o W/out/<名前>.pptx                       # C
python S/scripts/build_deck.py W/imported/scenario.json -o W/out/<名前>.pptx              # E
```

既存の資料に差し込む場合は、生成の前に差し込み先のデザインを目で確認する。スクリプトはマスターとテーマから合わせるため、スライドに直接付けた書式は拾えない。

```
python S/scripts/render_preview.py <既存.pptx> --out W/preview_base
```

- 差し込み位置の前後のスライドを開き、タイトルの位置・色・大きさ、本文の余白、ロゴや帯、フッターの内容を確認する
- マスターやテーマに無い書式（スライドごとに変えたタイトル色、スライド上に置いたロゴ・帯など）や、章ごとに違うフッターがあれば、生成後に手で合わせる箇所としてユーザーに伝える
- 手順5のQAでは、このプレビューと並べて比べる

生成は次のようにする。出力は別名にし、元の資料は上書きしない。

```
python S/scripts/build_deck.py W/scenario.json --captures W/captures --base <既存.pptx> --insert-at 3 -o W/out/<名前>.pptx
```

- `--sections`: 作るスライドを選ぶ（`cover,overview,steps,summary`。差し込み時の既定は表紙なし）
- `--only <shot id>`: その画面のスライドだけを作る（追加の表示パターンを1枚だけ差し込むときなど）
- 終了コード 3（`NG:`）ははみ出し。手順を分けるか文言を短くして作り直す
- `WARN:` も確認する。どの画面にも対応付けられていない項目や、赤枠のない手順がここに出る

### 5. 目視でQAする

```
python S/scripts/render_preview.py W/out/<名前>.pptx --out W/preview
```

Windows は PowerPoint で、それ以外は LibreOffice で描画する。全スライドを開き、下の QA チェックリストで確認する。直したら 4 からやり直す。

納品物は、作成過程を知らない新しいサブエージェントにプレビューPNGとチェックリストを渡してレビューさせると、作った本人が見落とす誤りを拾いやすい。

### 6. 報告する

ユーザーに次を伝える。

- pptx のパス
- スライド構成
- 置いた仮定（例: 1件目の商品を例示した）
- WARN の内容
- PowerPoint で微調整したほうがよい箇所

## 赤枠の付け方

- 入力欄・ボタン・リンクは要素そのものを囲む。取得項目は値の文字範囲を囲む（`kind: data` は自動で文字範囲に合わせる）
- 「ラベル＋値」で意味を持つ項目は、両方を含む親要素を `target` にする
- ハッシュ付きのクラス名は前方一致で書く（`[class*='ItemTitle_itemTitle']`）。サイト改修で末尾が変わっても動くようにするため
- 同じ文言が複数ある画面は `within` や `:has()` で範囲を絞る（例: 左メニューのショップ名と商品カードのショップ名）
- 隣り合う枠には自動で隙間が入る。番号は文字を隠さず、どの枠のものか紛れない位置に自動で置く。置き場所が悪いときは `label` で固定する

## 撮影の注意

- 入力直後に出るサジェストは、撮影前にフォーカスを外して閉じる（既定の動作）
- ポップアップやバナーは `setup` の `hide` で隠す。Cookie同意などは「同意」を押さない
- ヘッドレスブラウザ特有の UA で表示を変えるサイトがあるため、UA は通常の Chrome 表記に揃えている。例: au PAY マーケットはポイント表示が出なくなる
- 後から読み込まれる値には `wait_for` で値の表示条件を指定する（例: `{"css": ".price", "has_text": "円"}`）。座標は3回連続で安定するまで測り直してから撮る。待機上限は `browser.timeout_ms`（既定 30000）、画面・切り抜きごとの `timeout_ms` で変えられる。固定の `wait_ms` は補助として使う
- iframe 内は `target` に `frame`（セレクタ、入れ子なら外側からの配列）を付ける。赤枠は親ページ上の座標に変換される。画像マップの `area` は対応画像と `coords` から範囲を測る。指定例は scenario-format.md を参照
- ログイン・CAPTCHA・アクセス制限のある画面は自動化しない（突破を試みない）。その画面は C、保存済みの実行結果があるなら E に切り替える
- アクセスは資料作成に必要な最小限のページ数にとどめる

## QA チェックリスト（全スライド）

1. 手順N・項目Nの赤枠が、説明している要素を正しく囲んでいる
2. 赤枠同士が重なっていない。枠線が値の文字を横切っていない
3. 番号が文字を隠しておらず、どの枠の番号か一目で分かる
4. 切り出しでラベル・見出しが途中で切れていない。余白ばかりになっていない
5. ポップアップ・サジェスト・読み込み中の表示が写っていない。取得値が表示されている
6. 右パネルの文字がはみ出していない。表の行が読める大きさになっている
7. 画面から取る項目すべてに赤枠がある（WARN が無い）。グレーの項目は画面から取らない項目だけになっている
8. 技術情報（セレクタ・URLパラメータ・内部ID）が資料に出ていない。リンクは開けるページにだけ付いている
9. 差し込んだ場合は、前後の既存スライドとタイトル位置・色・フッターが揃っている

## 修正依頼への対応

- **文言の修正**: scenario.json の `text` / `detail` / `notes` / `title` を直し、手順4だけやり直す（撮り直し不要）
- **赤枠の位置**: 1回きりなら PowerPoint 上で直接動かしてよい。再生成で上書きされるため、恒久的に直すなら `target` か `box` を直す
- **手順や対象画面の変更**: 変更対象を合意し、scenario.json を直して `capture.py --only` でその shot だけ撮り直す。`target` を変えた shot は撮り直しが必要（build_deck.py が検出して止まる）
- **表示の違いの追加**
  1. 追加する表示差分と撮影範囲を合意してからリンクを開く。既存画像を再利用する場合は独立した表示パターンの shot（専用スライド）を足す
  2. `capture.py --only <追加したid>` で追加分だけ撮る。既存 shot に `peeks` を足す方法では親画面と既存の切り抜きも撮り直されるため、その全範囲が合意されている場合だけ使う
  3. 手直し済みの資料に足す場合は、`--base <手直し済み.pptx> --only <id> --insert-at <位置>` で差し込む
- **サイト改修後**: 撮り直す範囲を合意し、同じ scenario.json で対象だけ撮り直す。全画面更新を依頼されている場合は全体を再実行する

## ファイル

| パス | 用途 |
|---|---|
| `scripts/capture.py` | A/B/D: scenario.json に従ってブラウザを操作し、キャプチャ・赤枠座標・差分の切り抜き（captures/deck.json）を出す |
| `scripts/build_deck.py` | scenario（＋撮影結果）から pptx を生成する。既存資料への差し込み、切り出し・枠の間隔・番号の配置・スライド分割・はみ出し検出を行う |
| `scripts/render_preview.py` | pptx を1枚ずつ PNG にする（PowerPoint または LibreOffice） |
| `scripts/overlay.py` | C の座標読み取り用の目盛り画像と、枠の確認画像を作る |
| `scripts/import_results.py` | E: Playwright JSONレポートの添付PNGを一覧化し、選択した画像と座標をscenarioへ取り込む |
| `references/inputs.md` | 必要なもの（パターン別）とユーザーへの確認テンプレート |
| `references/import-results.md` | 実行結果の用意・添付画像の選択・インポート計画とコマンド |
| `references/scenario-format.md` | scenario.json の仕様、Playwright コードからの変換表 |
| `examples/aupay-market.json` | au PAY マーケット（検索 → ショップ絞り込み → 商品詳細、表示の違い2種）の完成例 |

依存: Python 3.10+、`python-pptx`、`Pillow`、`lxml`、`playwright`（A/B/D のみ。`playwright install chromium` が必要）。フォントは Meiryo UI（Windows 標準）を使う。差し込み時は差し込み先のテーマフォントを使う。
